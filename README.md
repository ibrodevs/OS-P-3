## Цель работы

Разобраться с процессами Linux на практике: читать информацию напрямую из `/proc`, создавать дочерние процессы через `fork`, заменять их программой через `exec`, увидеть состояния zombie/orphan и исследовать механизм Copy-on-Write.

## Что реализовано

- `ptree.py` строит дерево процессов текущего пользователя напрямую из `/proc`;
- `runner.py` запускает N дочерних процессов через `fork()` + `exec()` и собирает коды возврата;
- `zombie_demo.py` демонстрирует zombie-процесс;
- `orphan_demo.py` показывает переподчинение осиротевшего процесса;
- `cow_demo.py` демонстрирует Copy-on-Write и изменение показателей памяти после записи.

## Запуск

```bash
python3 ptree.py
python3 runner.py 3 -- /bin/sleep 1
python3 zombie_demo.py
python3 orphan_demo.py
python3 cow_demo.py --size-mb 64
```

> Работа ориентирована на Linux, потому что использует `/proc` и `os.fork()`.

## Ключевая идея

После `fork()` родитель и ребёнок логически имеют отдельные адресные пространства, но физические страницы памяти сначала могут использоваться совместно. При записи ядро копирует изменяемые страницы — это и есть **Copy-on-Write**. Zombie уже завершился, но ещё имеет запись в таблице процессов, пока родитель не вызовет `wait`; orphan продолжает работу после завершения родителя и получает нового родителя.

## Вывод

Процессы изолированы друг от друга, а Linux предоставляет подробную информацию об их состоянии через `/proc`. `fork` создаёт новый процесс, `exec` заменяет его код другой программой, а Copy-on-Write позволяет делать `fork` экономнее по памяти.
