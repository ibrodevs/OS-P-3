## Выполнение задания

### 1. Дерево процессов из `/proc`

`ptree.py` не использует команду `ps`. Скрипт самостоятельно проходит по каталогам `/proc/<PID>`, читает `/proc/<PID>/status`, определяет UID, PPID, состояние процесса, имя и использование памяти.

В результате формируется дерево процессов текущего пользователя.

Пример представления:

```text
bash (PID=..., state=S, RSS=... kB)
  python3 (PID=..., state=R, RSS=... kB)
```

Это показывает, что `/proc` предоставляет пользовательским программам структурированное представление внутренних данных ядра о процессах.

### 2. `fork()` и `exec()`

В `runner.py` родитель создаёт `N` дочерних процессов через `os.fork()`. Каждый ребёнок затем вызывает `os.execvp()` и полностью заменяет свой текущий образ другой программой.

Родитель ждёт завершения всех детей через `waitpid()` и выводит:

- PID;
- код возврата;
- причину завершения;
- время работы процесса.

Это демонстрирует стандартную модель Unix: **fork создаёт процесс, exec загружает в него новую программу**.

### 3. Zombie-процесс

`zombie_demo.py` создаёт ребёнка, который сразу завершается. Родитель намеренно некоторое время не вызывает `waitpid()`.

В этот момент завершившийся ребёнок остаётся в таблице процессов в состоянии `Z`:

```text
[python3] <defunct>
```

Zombie не выполняется и не использует обычное процессорное время, но его запись сохраняется, пока родитель не заберёт статус завершения через `wait()`/`waitpid()`.

### 4. Orphan-процесс

`orphan_demo.py` создаёт ребёнка, после чего родитель завершается раньше него. Ребёнок продолжает работу и получает нового родителя со стороны системного процесса/supervisor.

Это демонстрирует, что завершение родителя не обязано автоматически завершать дочерний процесс.

### 5. Copy-on-Write

`cow_demo.py` создаёт большой объект в памяти и затем выполняет `fork()`.

Сразу после `fork` родитель и ребёнок логически имеют разные адресные пространства, но физические страницы памяти могут временно использоваться совместно.

Когда ребёнок начинает изменять данные, ядро создаёт приватные копии изменяемых страниц. Такой механизм называется **Copy-on-Write (CoW)**.

Скрипт показывает показатели памяти до и после записи, включая RSS/PSS и private/shared dirty memory, чтобы продемонстрировать переход страниц из совместно используемых в приватные.

## Вывод

Работа показывает жизненный цикл процессов в Unix/Linux на практическом уровне. `/proc` позволяет наблюдать состояние процессов, `fork()` создаёт новый процесс, а `exec()` заменяет его программный образ. Zombie появляется, когда завершившийся ребёнок ещё не был обработан родителем, orphan продолжает работу после завершения родителя, а Copy-on-Write позволяет экономить память после `fork`, копируя страницы только при реальной записи.
